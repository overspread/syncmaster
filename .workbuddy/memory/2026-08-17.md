1. **`bundle.resources` glob 带 `..` 在 `tauri-build` 编译期会报 "path not found"**
   - 根因：tauri-build 解析 resources glob 的基准是 `target/debug/build/...`（编译目录），不是 `src-tauri`，所以 `../syncmaster/**` / `syncmaster/**` 都解析不到。
   - 临时方案（dev 已验证可跑）：`resources: []`。
   - **生产打包仍未解决**：需要 beforeBuildCommand 把 `syncmaster/` 拷进 `src-tauri/`（如 `src-tauri/webapp/`），resources 改 `["webapp/**"]`（无 `..`），main.rs 的 resolve_server_py 也要相应调整 —— 这步还没做，是 `tauri build` 发布前的待办。

2. **图标必须是 RGBA（32-bit）PNG**
   - 原先用 struct 手写的 PNG 是 24-bit RGB，Tauri `generate_context!` 报 "icon ... is not RGBA"。
   - 修复：装 Pillow，用 `_generate_py.py` 重生成所有图标（圆角蓝方块 + 双向箭头同步图标）。`src-tauri/icons/` 下全部 .png/.icns/.ico 已确认为 RGBA。

3. **main.rs 的 release-only 代码要加 `#[cfg(not(debug_assertions))]` 门控**
   - `Command` / `Context` / `AppHandle` / `Path` / `PathBuf` / `PYTHON_BIN` / `resolve_server_py` 只在生产打包（Rust 起 sidecar）用到，debug 下未用会报警告。已加门控，现在零警告。

4. **server.py 必须多线程**
   - 原 `HTTPServer` 单线程，WebView 用 keep-alive 占住连接后，外部并发请求（含 SSE 日志流）会被阻塞返回 000。
   - 修复：改 `ThreadingHTTPServer`。所有路由在并发下稳定 200。

## 生产打包（tauri build）资源问题 —— 已彻底解决（最后一段会话）

### 核心结论（关键，别再踩）
- **`frontendDist` 在「自定义 python http server」架构下不会被打进 bundle**。我们 window.url 指向 `http://127.0.0.1:9800`，Tauri 走 asset-protocol 的逻辑被跳过，所以 `Contents/Resources/` 里只有 `icon.icns`，server.py 不在。
- **必须用 `bundle.resources` 显式打包 webapp**。但 tauri-build 解析 resources 路径的基准是 **build 脚本 CWD**（实测 = `src-tauri`，不是 hash build 目录——之前误判了）。
- **resources 用 glob 形式 `webapp/**` 会报 "0 matches"**：Rust `glob` crate 的 `**` 在 `target/release/build/...` 上下文匹配 0 文件（踩坑确认过 `BUILD_SCRIPT_CWD=/Users/overspread/projects/syncmaster/src-tauri`，webapp 存在，glob 仍 0 匹配）。
- **正确写法：目录形式 `resources: ["webapp"]`（不带 glob）** → tauri-utils 走 `WalkDir` 递归拷贝，且 `resource_relpath` 生成干净的 `Resources/webapp/...` 路径。已验证 `.app/Contents/Resources/webapp/{server.py,static/,templates/}` 全部就位。

### 最终配置（src-tauri/tauri.conf.json）
- `build.frontendDist: "webapp"`（dev/build 校验用；实际由 resources 打包）
- `build.beforeDevCommand`: 用 Python shutil 把 `syncmaster/` 拷成 `src-tauri/webapp/`（忽略 __pycache__）后启动 python dev server
- `build.beforeBuildCommand`: 同上拷贝（无启动 server）
- `bundle.resources: ["webapp"]`（目录形式，关键）
- `src-tauri/webapp/` 已加进 `.gitignore`（build 期生成物）

### main.rs
- `resolve_server_py` 优先找 `resource_dir/webapp/server.py`（与打包布局一致），兼容 `syncmaster/` 和 flat 布局，最后 fallback 到 dev 布局。

### server.py 健壮性
- jinja2 缺失时自动 `pip install jinja2` 再 import（生产 App 依赖系统 python3，可能没装 jinja2）。
- 已改为 `ThreadingHTTPServer`。

### 验证结果（tauri build）
- release 编译 **0 警告**，`.app` 成功打包，`Contents/Resources/webapp/` 含完整 server.py + 8 模板 + static。
- 直接运行 bundle 内 server.py（系统 python3，端口 9811）→ `/`、`/categories`、`/monitor` 全部 200 ✅

### 发现的 bug 与修复（均在 syncmaster/server.py）
1. **🔴 严重-已修**：pull 方向同步逻辑错误且具破坏性。原代码无论 push/pull 都先 stage1(本地↔跳板机) 再 stage2(跳板机↔服务器)；pull 时 stage1 把跳板机空目录用 `--delete` 同步回本地 `~/.hermes`，会清空本地，且真正该取数据的 stage2 结果再不传回本地。重写 `run_sync_impl`：push=本地→跳板→服务器；pull=服务器→跳板→本地（顺序+方向都反转）。
2. **🟡 已修**：取消同步状态被覆盖 + 审计误记。新增全局 `sync_cancelled`；`cancel_sync` 设 cancelled 并广播"已取消"；`run_sync_impl` except 块在 `sync_cancelled` 时不再覆盖 status、不再重复广播、不再写"同步失败"审计。
3. **🟡 已修**：EXCLUDE_FILE 不存在时仍无条件 scp。改为仅当 `EXCLUDE_FILE.exists()` 才 scp，scp 失败(`check=True`)则退化为无排除，不阻塞同步。
4. **⚪ 已修**：`/api/category/save`、`/api/config/save` 直接 `json.loads(body)` 遇空/非 JSON 会 500 → 包 try/except 返回 400。
5. **⚪ 已修**：默认分类 `localPath` 存字面量 `~` → 用 `os.path.expanduser` 展开。

## 路径输入框点击弹系统选择器（爸爸："点击输入框弹出来选择 find 文件"）

### 方案
- 纯 Web（python http 预览）无法调系统文件选择器（浏览器安全限制拿不到真实绝对路径）；必须在 Tauri 壳内用 `tauri-plugin-dialog`。

### 改动
1. `src-tauri/Cargo.toml`：加 `tauri-plugin-dialog = "2"`。
2. `src-tauri/src/main.rs`：builder 链加 `.plugin(tauri_plugin_dialog::init())`。

### 🐞 修复：点击输入框弹不出 Finder（实测"没反应"）
- 根因：Tauri v2 全局模式下插件**不会**自动挂到 `window.__TAURI__`（只有核心 core API 在）。原 `pickPath` 用 `window.__TAURI__.dialog.open`，运行时 `window.__TAURI__.dialog` 为 undefined，静默走降级分支 return，毫无反应。
- 改法（绕过插件全局命名空间，只走必定存在的 core）：
  1. `main.rs`：新增 `#[tauri::command] async fn pick_path(window, directory) -> Result<Option<String>,String>`，内部用 `window.dialog().file().pick_folder/pick_file`（非阻塞回调式 + mpsc 通道等待，macOS 原生面板由插件 dispatch 到主线程，跨平台安全），`FilePath` 用 `.to_string()`；builder 加 `.invoke_handler(tauri::generate_handler![pick_path])`。
  2. `app.js` 的 `pickPath` 改为 `window.__TAURI__.core.invoke('pick_path', { directory })`.
  3. `capabilities`：试加 `core:command:default` 报 "not found"（此 Tauri 2.11.5 core 无 command 权限集）——自定义命令默认允许调用，去掉即可。
- 验证：`cargo check` dev profile 通过；`bash tauri-build.sh` 重新打包（29s），`.app`+`.dmg` 生成；覆盖桌面（挪旧版废纸篓）。新 app 内 `app.js` 含 `core.invoke('pick_path'`、binary `strings` 含 `pick_path`，确认编译进包。
- ⚠️ 教训：Tauri v2 自定义原生能力优先用 Rust 命令 + `core.invoke`，别依赖 `window.__TAURI__.<plugin>` 全局命名空间。
